# Native action dispatch checkpoint

The production CLI does not install this reader. The OSCAR action option stays
disabled by default. This checkpoint is for source review and operator
qualification. Deployment needs the matching A2 journal schema and A3 native
admission, followed by B1/B2 consumer commissioning. Release pins and CI
configuration are unchanged.

## Firing member identity and entry

The app adapter binds the A3 journal. It plans native routes with immutable
source labels and the effective severity view. A publication updates grouping,
inhibition sources and the local list view. The outgoing member retains its
provider pointer and exact expiry even when the notification copy freezes its
firing status. The group store keys members by the original provider identity.
Projected nflog hashes distinguish two source alerts with identical effective
labels.

The first verified private OSCAR callback enrolls the native identity. Every
tracked firing contact reserves episode and destination coverage. Explicit work
is selected by a durable operation ID. Its pending receiver, integration and
scope are revalidated on claim. Narrow notifier scopes can reach only the
canonical callback. Its signed delivery ID is derived from the original
operation and target. B2 must validate the signed scope, authorize each
downstream notifier and coalesce its individual receipt with ordinary fan-out.

The selected pipeline reads the group's baseline for managed eligibility and
sends only the selected member. It leaves the ordinary group log and clocks
alone. A successful native webhook response confirms transport acceptance.
B2 owns downstream notification and ticket results. An ambiguous response
keeps its entry held. The sender disables redirect following and request-body
replay for an entered webhook. Recovery may consume a still-pending target.
Fresh policy authority for a hold, expiry or successor comes from C3.

The ordinary reader stores a bounded membership summary of the owner's
recovered sources. A positive bit only selects the exact indexed journal
lookup. A missing candidate can obtain a local pass for its exact provider
pointer and live epoch. Source enrollment and direct entry compete under the
same local map guard. An uncertain direct entry retains its local fence. A
never-enrolled contact has no durable pre-entry row after process loss. A replacement owner retains ordinary native failover behavior for contacts made before identity enrollment. A later independently eligible contact can overlap a pre-enrollment contact whose result died with the owner. Cross-owner exclusion starts at durable enrollment.

## Graph and qualification limits

Action transport validation can distinguish a verified canonical private
callback from a direct native receiver. The managed conversion producer retains
its separate commissioning predicate. The dormant adapter handles the 18 registered integration kinds. Selected
dispatch supplies the selected alert and a detached copy of the group's
provider metadata. Slack retains its configured parent update and thread reply
behavior. A guarded first Slack post records an opaque binding for the assigned
channel and parent message in the ordinary provider metadata. An update of that
parent retains the original recipient identity and repeat deadline. A different
parent receives its own binding. Jira searches the existing group issue and applies its normal field
updates and transitions. These configured operations can replace the remote
group's displayed content. The local ordinary member set and repeat clock stay
with the ordinary pipeline.

Prepared destinations include actual template/file addresses and provider
routing fields. For dynamic identities the journal stores a length-delimited
HMAC digest of the integration configuration and length-delimited candidate
fields. The existing private authority transaction stores a stable random
recipient key. A compatible native owner obtains it in its authenticated lease.
Renewal or replacement using rotated authentication keeps the same prepared
target keys, pending and unknown ownership, and repeat deadlines. The original
entry token can settle its original row. Canonical signing retains its separate
callback credential. A direct-only graph requires no callback credential.

The paired native reader and store require recipient-binding protocol version 2
and the updated authority migration. A missing stored namespace version holds
retained work even after import of the exact prior key. For example, current
SNS identities include file headers absent from legacy digests. Resuming a
retained namespace requires independently verified ownership mapping or
reconciliation of its pending, unknown and confirmed coverage. The migration
leaves existing namespaces unmarked. Original entry tokens can settle during
the hold. An incompatible renewal, including a permanent redirect from the private endpoint, immediately fences local entry. A transient
outage leaves only the balance of the existing lease.

For group-dependent recipients the ordinary reader inspects already-tracked
candidates under their current route, variant and lifecycle. It removes
covered/held members, rerenders the remaining group's route labels and address,
and checks the final cohort before its reservation CAS. Each inspection is
indexed and the reader reuses results for an unchanged member and digest
within the same flush. After 16 reductions it holds for another evaluation.
Previously admitted selected targets revalidate independently if a sibling's
recipient file becomes unavailable, including during non-policy permit renewal.
The frozen accepted target set survives renewal. Entry still requires current
eligibility for the individual target. Firing reservations bind the inspected
source, severity revision, lifecycle and outgoing labels. After partial
confirmation, a held resolved sibling stays due across native group cleanup.
While that hold persists, the prior notification log suppresses already
acknowledged direct clears. Reobserving a completed sibling preserves the
group timestamp. A firing sibling can repeat at its recorded native deadline.
When incident.io truncates an incomplete group to an acknowledged firing repeat
and leaves an eligible, unacknowledged member out, the sender defers acknowledged
firing repeats from both tracked and direct sources. It encodes the remaining
members in native order and includes every size omission in `truncatedAlerts`
alongside omissions from `max_alerts`. The ordinary log records newly delivered
members from either source. A replay of an accepted operator intent whose
targets all settled with conclusive no-effect evidence returns the stored
operation and its individual receipts during reconciliation.

On guarded HTTP mutations the native client retains configured authentication,
CA, proxy and pooled connections. A separate HTTP/1 pool gives each active
request exclusive use of its connection. The sender checks admission after
connection acquisition and closes the connection before a rejected write. A
second connection attempt cannot repeat a submitted mutation. HTTP/2 shares
connections between streams, so closing a connection there could interrupt
unrelated requests. Ordinary capability-off requests use their configured
protocol. The native probe of a changed destination holds the original claim
for no-effect reconciliation. Provider accept/drop outcomes remain unknown.

SMTP renders before DATA and checks again before committing the final dot.
Telegram uses an invocation-local bot and preserves native timeouts. Oversized
HTML that would replace all alert content with a generic diagnostic fails
before a tracked write. Ordinary untracked notifications retain the configured
fallback. SNS guards the signed Publish request with a single SDK attempt.
Selected FIFO deduplication uses the logical action and target while preserving
the native message group. Slack, OpsGenie and Jira authorize each distinct write
and retain an earlier possible effect if a later write fails. Jira can resolve
with zero effects when the group has no matching issue. Incident.io records
the exact encoded member prefix. It renders status, common fields, route labels
and metadata from that prefix before terminal reservation. The ordinary group
log retains accepted members, and a pending resolved tail holds dispatcher
cleanup through the next flush. Jira resolved no-send completes the ordinary
group lifecycle while leaving contact coverage untouched. Provider transport acceptance and downstream OSCAR ticket
settlement have distinct receipts.

Tracked ordinary resolution uses the private `reserve-terminal` command after
normal group eligibility, send-resolved filtering and webhook truncation.
The journal derives the operation ID from the retained episode row, variant,
terminal sequence and destination. Claim rechecks current terminal identity,
the exact original source pointer and expiry, routing, suppression and the
lease. A later due flush with identical frozen evidence can renew a terminal
permit after expiry if its durable target has never received an entry token.
This includes a pending target that recovery closed solely for permit expiry.
An entered target keeps its receipt after re-fire. A canonical callback
carries a stable delivery UUID and ordinary lifecycle semantics. An independent
firing action cannot use a terminal claim. The claim does not advance a repeat
or reserve firing coverage.

Selection preserves ordinary input order. The native retry stage first applies
send-resolved, then the action reader fixes the webhook prefix before any
identity enrollment or reservation. The group log retains ordinary membership
after a successful truncated send. A limited batch with an unverifiable input waits for a fresh group. A direct sibling accepted beside a covered member enters the ordinary group log. Its next flush uses that receipt and preserves the covered member’s durable repeat deadline. A partial group-log update retains previously acknowledged siblings still present in the same state. Only members actually selected for
provider entry receive a claim. Prior confirmed terminal contacts may be

and notification readers on the existing native pipeline. An active reader

Measure three separate workloads. A proven untracked direct destination should
add no journal HTTP or SQL operation on the negative path. First canonical
binding pays for durable native identity creation. Repeated canonical no-policy
traffic includes lifecycle, delivery and coverage costs. D1–D3 must keep this
cohort in the same-work before/after latency comparison and meet the existing
5% threshold. Measure a 150-minute loaded interval plus drain. Timings from
static inspection or source compilation cannot establish these properties.
